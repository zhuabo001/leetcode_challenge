# 并查集 (Disjoint Set Union, DSU)

并查集是一种用于处理不相交集合的合并及查询问题的数据结构。

## 核心思想

- **初始化**：每个元素自成一个集合
- **查找 (find)**：找到元素所属集合的根节点（路径压缩优化）
- **合并 (union)**：将两个集合合并为一个集合

## 模版代码

```javascript
/**
 * 并查集类
 * 用于管理一组不相交的集合，支持合并和查询操作
 */
class DisjointSet {
  /**
   * 构造函数
   * @param {number} size - 初始化集合的大小
   */
  constructor(size) {
    // parent 数组存储每个元素的父节点
    // 初始化时，每个元素的父节点是自身
    this.parent = new Array(size).fill(0).map((_, i) => i);
  }

  /**
   * 查找操作：找到元素 x 所属集合的根节点
   * 使用路径压缩优化，将查找路径上的所有节点直接指向根节点
   * @param {number} x - 要查找的元素
   * @returns {number} 根节点的索引
   */
  find(x) {
    // 如果 x 不是根节点，递归查找其父节点并进行路径压缩
    if (this.parent[x] !== x) {
      // 路径压缩：将当前节点的父节点直接指向根节点
      this.parent[x] = this.find(this.parent[x]);
    }
    // 返回 x 的根节点
    return this.parent[x];
  }

  /**
   * 合并操作：将两个元素所在的集合合并为一个集合
   * @param {number} x - 第一个元素
   * @param {number} y - 第二个元素
   */
  union(x, y) {
    // 分别找到 x 和 y 的根节点
    const rootX = this.find(x);
    const rootY = this.find(y);

    // 如果两个元素不在同一个集合中，则进行合并
    if (rootX !== rootY) {
      // 将 rootX 的父节点指向 rootY，完成合并
      this.parent[rootX] = rootY;
    }
  }

  /**
   * 判断两个元素是否在同一个集合中
   * @param {number} x - 第一个元素
   * @param {number} y - 第二个元素
   * @returns {boolean} 如果在同一个集合返回 true，否则返回 false
   */
  isConnected(x, y) {
    // 比较两个元素的根节点是否相同
    return this.find(x) === this.find(y);
  }
}
```

## 使用示例 (lc684 冗余连接)

```javascript
/**
 * 查找冗余连接
 * 给定一个 n 个节点的树中添加一条边后的图，找出一条可以删去的边
 * 删除后可使得剩余部分是一个有着 n 个节点的树
 * @param {number[][]} edges - 二维数组，表示图中的边
 * @returns {number[]} 需要删除的边
 */
const findRedundantConnection = (edges) => {
  // n 条边对应 n 个节点
  const n = edges.length;
  // 初始化并查集，节点编号从 1 到 n，所以大小为 n + 1
  const dsu = new DisjointSet(n + 1);

  // 遍历所有边
  for (const [start, end] of edges) {
    // 如果 start 和 end 已经在同一个集合中，说明这条边是冗余的
    // 直接返回这条边
    if (dsu.isConnected(start, end)) {
      return [start, end];
    }
    // 否则，将这条边连接的两个节点合并到同一个集合中
    dsu.union(start, end);
  }
  // 如果没有找到冗余边，返回空数组（理论上不会出现这种情况）
  return [];
};
```

## 关键点

1. **路径压缩**：在 find 操作中，将查找路径上的所有节点直接指向根节点，大幅降低后续查找的时间复杂度
2. **按秩合并**（可选优化）：将深度较小的树合并到深度较大的树上，可以进一步平衡树的高度
3. **时间复杂度**：近似 O(α(n))，其中 α 是反阿克曼函数，增长极其缓慢，几乎可以认为是常数时间

## 总结和疑问

### 总结

1. 首先初始化一个父节点数组，内部存放的是题目给出数组中各自元素的父节点，初始值为给出数组中各自元素的自身索引

2. 路径压缩，定义 find 函数，用于查找元素 x 所在集合的根节点。核心思想是查找根节点的过程中，将路径上所有节点的父节点直接指向根节点。
3. 合并集合， 两个元素所属的集合若不是同一个，则进行合并，定义一个函数 union， 分别调用 find 函数找到各自集合的根节点，判断根节点是否相同（两个元素是否在同一个集合中），然后通过将其中一个元素所在集合的根节点的父节点指向另一个元素所在集合的根节点进行集合合并

4. 定义一个 isConnected 函数用来判断两个元素是否处于同一个集合

### 疑问

1. 怎么理解`路径压缩：将当前节点的父节点直接指向根节点`?

#### 解答

##### 路径压缩详解（以 lc684 为例）

###### 题目示例

```
edges = [[1,2], [2,3], [1,3]]
```

第三条边 `[1,3]` 是冗余边，因为 1 和 3 已经通过 1→2→3 连通了。

---

**初始状态**

```javascript
parent = [0, 1, 2, 3];
//          ↑  ↑  ↑  ↑
//          0  1  2  3  (索引)
```

每个节点都是自己的根节点（独立集合）。

---

**处理第一条边 `[1,2]`**

```javascript
find(1) = 1    // parent[1] === 1，直接返回
find(2) = 2    // parent[2] === 2，直接返回
union(1, 2): parent[1] = 2
```

**结果**：

```
parent = [0, 2, 2, 3]
          ↑  ↑  ↑  ↑
          0  1→2 2  3
```

---

**处理第二条边 `[2,3]`**

```javascript
find(2) = 2    // parent[2] === 2，直接返回
find(3) = 3    // parent[3] === 3，直接返回
union(2, 3): parent[2] = 3
```

**结果**：

```
parent = [0, 2, 3, 3]
          ↑  ↑  ↑  ↑
          0  1→2→3 3
```

树的结构：`1 → 2 → 3`，3 是根节点。

---

**处理第三条边 `[1,3]`（关键！）**

**执行 `find(1)` 时**：要找到 1 的根节点

```javascript
// find(1) 开始执行
parent[1] !== 1  // true (parent[1] = 2)
  → parent[1] = find(parent[1]) = find(2)

  // find(2) 开始执行
  parent[2] !== 2  // true (parent[2] = 3)
    → parent[2] = find(parent[2]) = find(3)

    // find(3) 开始执行
    parent[3] === 3  // true，返回 3
    // find(3) 结束，返回 3

  // find(2) 继续
  parent[2] = 3  // 路径压缩：2 直接指向根 3
  return 3
  // find(2) 结束，返回 3

// find(1) 继续
parent[1] = 3  // 路径压缩：1 直接指向根 3
return 3
// find(1) 结束，返回 3
```

**执行 `find(3)` 时**：直接返回 3

**比较**：`find(1) === find(3)` → `3 === 3` → 返回 `[1, 3]`

---

**路径压缩后的结果**

```javascript
parent = [0, 3, 3, 3]
          ↑  ↑  ↑  ↑
          0  1→3 2→3 3
```

**变化对比**：

| 节点 | 压缩前 | 压缩后 |
| ---- | ------ | ------ |
| 1    | 2      | 3      |
| 2    | 3      | 3      |
| 3    | 3      | 3      |

---

**总结**

| 步骤       | 树结构                | find(1) 的路径 |
| ---------- | --------------------- | -------------- |
| 初始       | `1 → 1`               | `1`            |
| 加边 [1,2] | `1 → 2 → 2`           | `1 → 2`        |
| 加边 [2,3] | `1 → 2 → 3 → 3`       | `1 → 2 → 3`    |
| 查找后     | `1 → 3, 2 → 3, 3 → 3` | `1 → 3`        |

**路径压缩的效果**：下次再调用 `find(1)` 或 `find(2)` 时，直接得到根节点 3，无需再遍历中间节点。
